# 4. Schemas and lenses

A schema is a message's shape: field names and types, never values. Lenses map schemas into one shared view (`contoso-task`: task_id, title, owner, due). One mapping serves every message of a schema.

| Schema | Operation | Fields | Mapped by |
|---|---|---|---|
| `0141792985c3…` | task | due, operation, owner, priority, profile, task_id, title | contoso-tasks |
| `3e87d298b567…` | reaction | emoji, id, operation, profile | waiting for a lens |
| `66eef2cca389…` | task | due, operation, owner, profile, summary, task_id | contoso-tasks |
| `6785664ffe00…` | task | due, operation, owner, profile, task_id, title | contoso-tasks |
| `dff381bc5e7f…` | task | assignee, id, operation, profile, text | phone-tasks |

| Lens version | How it became active |
|---|---|
| contoso-tasks v1 | adopted by the policy's quorum |
| phone-tasks v1 | adopted by the policy's quorum |
| contoso-tasks v2 | learned automatically (new fields only) |
| contoso-tasks v3 | adopted by the policy's quorum |

- When the laptop app added `priority`, the schema only gained a field, so v2 was learned automatically; `priority` is reported as dropped until someone maps it.
- When the tablet renamed `title` to `summary`, a person had to teach v3. Two peers adopted it, and the laws held: every old task still means the same.
- A careless v4 that rewrote every owner as `team` had two signatures, but the laws refused it. Signatures cannot override meaning.
- Blake's phone started sending reactions: that schema waits for a lens while everything else keeps working.
- Frankie's quarantined task added an `invoice` field. Only members' messages can teach the Hive a new shape, so nothing was learned from it.
